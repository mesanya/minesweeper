# Критерии оценивания промежуточных проектов

Обязательные критерии:

- Наличие презентации
- Наличие продукта
- GIT
- Выступление
- Понимание кода
- Комментарии (max 20% от проекта)

### 1. Техническая реализация ( 30 баллов )

*Здесь оценивается, работает ли продукт и насколько он «живой».*

- **Работоспособность (10 б.):** Проект запускается без критических ошибок. Основной сценарий (кейс использования) выполняется до конца.
- **Использование инструментов (15 б.):** Умение пользоваться Git (хотя бы базовые commit/push), наличие README-файла с инструкцией по запуску, использование среды разработки (IDE) и линтеров.
- **Соответствие стеку (5 б.):** Проект сделан на технологиях, которые изучались на курсе (например, Python/JS/HTML+CSS), а не скачан целиком из интернета с непонятным кодом.

### 2. Функциональность и полнота (20 баллов)

- **Реализация ТЗ (10 б.):** Все заявленные в начале функции работают. Если что-то не сделано — это честно описано в README (это плюс, а не минус).
- **UX/UI (10 б.):** Интерфейс (если есть) понятен без инструкции. Кнопки нажимаются, текст читаем, нет «вырвиглазных» цветов.

### 3. Презентация и защита (45 баллов)

- **Демонстрация (15 б.):** Наличие презентации, студент показывает **работающий** проект (или видео-демо), а не просто слайды. Отвечает на вопросы «А что будет, если...?».
- **Понимание кода (20 б.):** Студент может объяснить, что делает конкретная функция/строка, которую он написал.
- **Качество выступления (10 б)** Студент не читает, не мямлит, говорит четко и по факту, чувствется знание материала

### 4. Дополнительные баллы (25 баллов)

- **Командная работа (15 б):** Виден вклад каждого (например, через историю коммитов в Git). Нет ситуации «один делает всё, остальные спят».
- **Документация (5б):** Красивый и понятный README с картинками/скриншотами.
- **Креативность (5б):** Небанальная тема (не очередной «To-Do List», а, например, «Трекер полива растений» или «Бот для расписания»).

---

### Шкала перевода в оценку:

- **85–100:** Отлично. Проект работает, код чистый, студент всё понимает.
- **70–84:** Хорошо. Есть мелкие баги или недочеты в дизайне, но в целом всё отлично.
- **50–69:** Удовлетворительно. Работает только базовая часть, код «спагетти», но студент старался и может объяснить основы.
- **0–49:** Неудовлетворительно. Проект не запускается, студент не может ответить на элементарные вопросы по своему же коду (или проект скачан).
